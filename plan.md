# Branch 4 — Chinese translation pilot (`claude/add-multi-language-support-ls4KF`)

Part of the howtoaicode.com investment plan. This branch enables Starlight i18n, adds a one-shot Claude-API translation script, and ships Chinese (Simplified) as a beta. Merge order: best after `claude/seo-aeo-geo` so the consolidated Head component is ready to host hreflang tags.

**Future languages (Spanish, Portuguese, etc.) are each their own branch** that reuses the script — `claude/i18n-es`, `claude/i18n-pt-BR`, …

## Why

The course is English-only today and reaches a small slice of the global beginner-developer audience. A Chinese (Simplified) translation:
- Opens up the largest non-English developer audience
- Validates the translation pipeline cheaply (one language, partial site) before committing to more
- Sets the pattern (`script + beta banner + hreflang + noindex-until-reviewed`) for every future language

Quality is hedged with a visible "machine-translated" banner and a `noindex` flag per page that can be flipped off once a translation is human-reviewed.

## Approach (the "lightest, cheapest" path)

- Translations are generated by a Node script in `scripts/translate.mjs` that the maintainer runs on demand (no GitHub Action; no CI auto-commits). API cost for the pilot scope is well under $1 with Claude Sonnet.
- A manifest tracks source-file hashes so re-runs only translate pages that changed.
- Pilot scope intentionally excludes the long tail (Level Up, Optional, Reference, About) — those translate later once we trust the flow.

## Changes

- [ ] `astro.config.mjs` — enable Starlight i18n:
  ```js
  defaultLocale: 'en',
  locales: {
    en: { label: 'English', lang: 'en' },
    'zh-CN': { label: '简体中文', lang: 'zh-CN' },
  }
  ```
  Starlight will auto-inject a **language switcher in the site header next to the search bar** — no extra component needed.
- [ ] Restructure existing content: move `src/content/docs/*` → `src/content/docs/en/*` (Starlight convention when `defaultLocale` is set). Update internal links if any reference the bare slug without the locale prefix.
- [ ] `scripts/translate.mjs` — Node script using `@anthropic-ai/sdk`:
  - CLI flags: `--lang zh-CN`, `--section <path>`, `--dry-run`, `--force`
  - Reads English `.md` from `src/content/docs/en/<section>/`, calls Claude Sonnet 4.6 with a translation prompt that preserves frontmatter keys, code blocks, MDX components, and Starlight directives
  - Writes to `src/content/docs/zh-CN/<section>/`
  - Tracks source-file hashes in `scripts/.translation-manifest.json` so re-runs only translate changed files
  - Reads `ANTHROPIC_API_KEY` from env
- [ ] `package.json` — add `@anthropic-ai/sdk` dep + `"translate": "node scripts/translate.mjs"` script
- [ ] `src/components/BetaTranslationBanner.astro` (new) — registered via Starlight's `components.Banner` override; renders only on non-English pages (detect via `Astro.currentLocale`). Copy: *"This page was machine-translated from English. Spotted an issue? [Report it on GitHub]."*
- [ ] Per-page `noindex` meta on Chinese pages by default — extended in the Head component (continued from Branch 2). Removable per-page by setting `reviewed: true` in frontmatter.
- [ ] `hreflang` alternate links injected by the Head component (Branch 2 reserved the helper; Branch 4 plugs in the locale list).

## Verify before merging

1. `ANTHROPIC_API_KEY=... npm run translate -- --lang zh-CN --section start-here` — files appear in `src/content/docs/zh-CN/start-here/`
2. Eyeball one translated page for obvious errors before scaling up
3. `npm run dev` → visit `/zh-CN/` — beta banner is visible, content is in Chinese, headings/code blocks intact
4. The Starlight-rendered language switcher (top header, next to search) is present; clicking it round-trips EN ↔ zh-CN with the same URL slug
5. Page source: `<html lang="zh-CN">`, hreflang `<link>` tags pointing at the English alt, `noindex` meta present
6. Build cost estimate: under $1 for the pilot sections with Sonnet
